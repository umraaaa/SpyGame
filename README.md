# 臥底遊戲 🕵️

派對遊戲。多數參與者拿到「平民題」，少數拿到「臥底題」，投票者透過討論把臥底揪出來。

開房時決定兩個維度：
- **內容**：🎵 歌曲（iTunes 搜尋＋試聽）／ ✏️ 單詞（純文字）
- **表決**：🔁 多次（殺到臥底全滅或臥底追平平民才結束回合）／ 1️⃣ 單次（投一次就結束回合）

## 部署（GitHub Pages）

純靜態三個檔案（`index.html` / `style.css` / `app.js`），推上 repo 開 Pages 即可，不需要後端或 NAS。

## 架構

- **連線**：PeerJS 點對點。開房者的裝置就是主機，其他人輸入 4 碼房號直連。房主關網頁房間就消失。
- **iTunes 搜尋 / 試聽**：在每個人自己的裝置上以 JSONP 呼叫，只有選定歌曲的 preview url 傳給房主。
- **狀態**：房主持有唯一狀態，依身分裁切後推給每個人（臥底身分、別人的題目、答案都不外洩）。

## 角色與人數

- 最少 **10 人**（`app.js` 的 `MIN_PLAYERS`，要少人測試就調小）。
- **參與者 7 成**（拿題、被討論）、**投票者 3 成**（投票找臥底）。
- **出題者**一定在投票者裡，且**不能投票**（他知道答案）。
- **臥底數**（依參與者人數）：≤5→1、6~8→2、9~11→3…（每 3 人多 1），至少留 1 個平民。

## 每回合流程

1. **準備看題**：參與者按準備 → 倒數 3 秒 →（歌曲：同時播放／單詞：亮出詞）
2. **討論**：參與者描述自己的題；投票者畫面顯示「討論、鎖定臥底」；歌曲模式房主可複盤（有確認）
3. **房主確認討論完成** → 進入投票
4. **投票**：投票者投一位參與者，誰投誰公開；平票時最高票的人重投，再平票這輪不殺
5. **公布結果**：某人出局／是否臥底；多次表決會判斷是否繼續（臥底全滅＝平民勝、臥底≥平民＝臥底勝）
6. **公布所有詞條** → 房主確認進入下一回合（**題庫不清空**）

## 題庫

每人有自己的私有 Queue，可一直加題（每題 = 平民 + 臥底），每回合消掉被抽中出題者的最前面一題。加入時會擋掉「平民＝臥底」與「與自己題庫內完全相同」的題目。

## 已知限制（prototype）

- 重新整理頁面 = 離開房間，沒有斷線重連
- 沒有跨回合計分
- 卡住時不自動跳過：準備 / 播放 / 投票階段房主都有「強制推進」按鈕（含確認）
